# 성능 실측

선택한 최종 코어와 재사용 실험을 같은 호스트의 Release 빌드에서 측정했습니다. 최종 코어 해시: `cc9004a4733fd01b5c87e67f6df04a97f841746f8c5e7fdfafdd9a3aeb42799a`.

- CPU: AMD EPYC 9V45 96-Core Processor
- OS: Linux-6.18.57-x86_64-with-glibc2.41
- 컴파일러: cc (Debian 14.2.0-19) 14.2.0
- 옵션: ` -O3 -DNDEBUG`; LTO 없음.
- OpenSSL: 3.5.7. 런타임 문자열은 각 원시 표본에 기록합니다.
- OpenSSL 자동 CPU dispatch를 사용했습니다. 실제 선택된 하드웨어 가속 경로는 확인하지 않았습니다. CPU affinity는 고정하지 않았습니다.

각 모드는 보정 후 200ms 이상인 표본 5개를 수집합니다. C 내부 루프·플랫폼 단조 시간원을 쓰고 입력 생성은 측정 밖입니다. 키/tweak 준비의 공개 API 할당·소거·해제를 포함합니다. 새 tweak 입력은 각 측정 안에서 순차적으로 서로 다릅니다. 128회 warmup 후 측정하며 calibration 표본도 보존합니다. 준비만 하는 모드의 체크섬은 반환 컨텍스트 주소와 성공 상태를 관측하고, 블록 모드는 결과 바이트를 관측합니다. 별도 SHAKE 호출 수 시험이 계산 경계를 확인합니다.

| 측정 모드 | 최종 채택 코어 중앙값 ns/op | 미채택 재사용 실험 ns/op | 변화 |
| --- | ---: | ---: | ---: |
| 준비된 암호화 | 128.160 | 119.452 | -6.79% |
| 새 키 준비 | 900.153 | 903.199 | +0.34% |
| 새 tweak 준비 | 4107.416 | 4232.245 | +3.04% |
| 새 tweak + 블록 | 4419.456 | 4045.721 | -8.46% |
| 새 키 + tweak + 블록 | 5183.002 | 5671.979 | +9.43% |
| 준비된 복호화 | 118.697 | 131.631 | +10.90% |
| AES-256 ECB 준비된 Update | 12.792 | 13.835 | +8.15% |
| AES-256 ECB 새 키 + 블록 | 368.958 | 365.871 | -0.84% |

코어 자체를 바꾸지 않은 실험에서 준비된 블록/AES 참고값도 흔들렸습니다. 이는 호스트 측정 변동을 보여 줍니다. 재사용의 일관된 개선을 입증하지 못해 채택하지 않았습니다. 과거 감사의 0.164µs/5.085µs는 이번 수치나 합격선으로 사용하지 않았습니다.

[최종 채택 코어 원시 JSON](../bench/results/baseline.json)과 [재사용 실험 JSON](../bench/results/context-reuse-trial.json)에 표본·중앙값·최소·최대·ns/op·ops/s·해시를 보존했습니다. 블록 처리 모드에만 16바이트 기준 MiB/s를 기록하며 준비 작업에는 처리량을 붙이지 않습니다.

AES-256 ECB는 tweak·인증을 제공하지 않는 별도 참고 primitive입니다. 준비된 모드는 기존 EVP 컨텍스트의 16바이트 Update 한 번이고, 새 키 모드는 컨텍스트 생성·키 초기화·Update·Final·해제를 포함합니다. 다른 API와 기능 경계를 동등한 암호로 주장하지 않습니다.

## 연구 재실행

[최종 전체 연구](../research/results/final-full.json)는 completed이며 고정 차분 1,572,864쌍과 관련 tweak 655,360쌍을 전부 실행했습니다. [보안 문서](security_ko.md)에 성공한 공격의 라운드 범위와 미해결 문제를 구분합니다. 재사용 실험의 전체 counts도 [별도 결과](../research/results/context-reuse-trial-full.json)에 남겼고 최종 코어와 동일합니다.
